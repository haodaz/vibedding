# 门槛地图：门外汉到底被什么拦住了

日期：2026-09-28

## 一个观察
一个做了 13 年产品、能读懂大部分代码、和 AI 一起写过好几个能跑的项目的人，说自己"无法开始一个真正的项目"。拦住 TA 的不是 C 语言、不是电路、不是算法，而是：

> 搞环境、搞 git、写终端命令。

也就是说：**门槛不在知识里，在知识之前。** 是启动摩擦，是"我不知道我不知道什么"，是每一步都可能报错而报错信息只对内行友好。

这个平台真正要解决的就是这层东西。嵌入式只是第一个试验田，因为它的启动摩擦特别大（多了一层"电脑 ↔ 芯片"的链路）。方法如果在这里成立，可以复制到任何有门槛的专业。

## 门槛分层
| 层 | 门外汉的感受 | 内行为什么不觉得难 | 平台的应对 |
|---|---|---|---|
| **① 环境** | 装了半天还报错，不知道装的是什么 | 装过一百次，报错一眼认出 | 一键脚本 `tools/setup-mac.sh` + 体检脚本 `check-env.sh`，把"装环境"变成"跑一条命令，看到全绿" |
| **② 终端** | 一个黑框，不知道能输什么，怕输错 | 十几条命令肌肉记忆 | 只教 8 条；每条命令配"它做什么 / 成功长什么样 / 失败怎么办"；平台里每条命令都能直接复制 |
| **③ git** | 概念太多（分支、暂存区、rebase…），怕搞坏 | 只用 5 条命令过日子 | 只教 5 条，讲成"存档点"；其他等真需要再学 |
| **④ 链路** | 不知道代码怎么"到"芯片里 | 见过整条链路 | 模块 0 专门走链路，一张图把每一环画出来 |
| **⑤ 报错** | 满屏红字，不知道看哪 | 知道真原因在倒数第 10 行 | 报错求助模板 + "让 AI 列 3 个原因和验证方法" |
| **⑥ 不知道下一步** | 教程学完了，然后呢？ | 有项目驱动 | 任务卡 + 学习路径，每步有看得见的结果 |
| **⑦ 不知道 AI 能不能信** | 它说得很肯定，但错了 | 有经验判断 | `prompts/04-ai-lies.md` 持续积累，任务卡里标出核对点 |

①②③ 是**通用门槛**，任何编程相关的领域都有。④⑤ 是嵌入式特有加重。⑥⑦ 是 AI 时代的新门槛。

## 三条设计原则
1. **让 AI 跑，人来看。** 终端命令优先由 AI 执行（Claude Code / Cursor），人负责看结果、做判断。人不需要"会敲"，需要"会看"。
2. **文件即真身。** 所有东西都是本地 markdown 和代码，AI 和网页读写同一批文件。不依赖任何平台账号，随时能 fork、能带走。（这条从用户自己的 applyspace 项目学来的）
3. **每一步都有可观察的成功标志。** "全绿"、"灯亮"、"看到 hello"。看不见的进步不算进步。

## 成功的样子
一个非科班的人，拿到一块板子、打开这个平台、旁边开着一个 AI，**不问任何真人**，两个周末内走完模块 0 和模块 1。中途卡住的每一处，都会被记进日志，变成下一版的任务卡内容。

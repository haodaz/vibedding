# 平台框架设计 v0.1

日期：2026-09-28 · 状态：第一版，板子还没到

## 0. 使命
把门槛拆掉，让人专注宝贵的部分：**实现自己的一个思路，对一件事大胆尝试，在一个原本无法掌握的领域做出点价值。**

门槛（环境、终端、git、报错、链路）是内行的日常、门外汉的高墙。它们不产生价值，只是挡在价值前面。平台的工作就是把这些墙一块块拆成台阶。见 [02-barrier-map.md](02-barrier-map.md)。

## 1. 我们在做什么
一个**边学边长**的平台。它有两个用户：
- **现在的我**：需要一条清晰的路、一个记录的地方、一套问 AI 的方法
- **以后的门外汉**：拿到一块板子和一个 AI，想知道从哪开始、下一步做什么、AI 说的能不能信

这两个用户的需求高度重合，所以"我学习时产生的东西"经过很少的整理就是"给别人的课程"。这是整个设计的核心押注。

## 2. 三层内容模型
```
日志 (journal)        原始、按天、有情绪、有弯路        →  真实
   ↓ 提炼
任务 (curriculum)     结构化、有验收、有常见坑          →  可复用
   ↓ 沉淀
提示词 & 硬件笔记      跨任务的方法论和事实             →  可信
```
- 日志是**源头**，写得越真实越好，包括 AI 说错的地方
- 任务是**产品**，每张卡都要能让一个陌生人独立完成
- 提示词库和硬件笔记是**基础设施**，每个任务都会引用它们

## 3. 一张任务卡的结构
```
frontmatter: title / goal / hardware / time / status
要做什么      一段话，说清楚为什么做这个
步骤          命令能直接复制
验收          checkbox，可观察的现象，不是"理解了 X"
问 AI 的时候  这个任务特有的提问建议
常见坑        表格：现象 → 原因
```
`goal` 必须是一个**看得见的结果**。"LED 眨眼"可以，"理解 GPIO"不行。

## 4. 课程路线（v0.1）
| 模块 | 主题 | 核心概念 | 为什么在这个位置 |
|---|---|---|---|
| 0 起飞前 | 工具链、认板子、第一次烧录 | 编译 → 烧录链路 | 消除硬件恐惧，先看到灯亮 |
| 1 点灯 | GPIO 输出/输入、PWM | 电平、上拉、占空比 | 最便宜的教具，建立肌肉记忆 |
| 2 会说话 | 串口收发 | UART、波特率 | 解锁 printf 调试，效率翻倍 |
| 3 感知世界 | ADC、传感器库、I2C 屏 | 模拟量、总线、第三方库 | 套件里的模块开始有用 |
| 4 时间的艺术 | millis、中断、状态机 | 非阻塞、volatile | 从"玩"到"能做东西"的分水岭 |
| 5 剥洋葱 | HAL、寄存器、读手册 | 时钟树、寄存器映射 | 有了直觉再看底层，不会被吓跑 |
| 6 综合项目 | 自选题目 | 需求拆解 | 把碎片拼成作品 |
| 7+（远期） | RTOS、低功耗、SPI/CAN、PCB | | 视兴趣 |

技术路线：**Arduino 框架起步 → HAL → 寄存器**。同一个 blink 写三遍，每一遍都比上一遍更接近硅片。

## 5. 技术选型
| 选择 | 方案 | 理由 | 放弃了什么 |
|---|---|---|---|
| 固件构建 | PlatformIO CLI | 命令行，AI 能直接跑；自动装编译器；跨板子 | STM32CubeIDE（图形界面，AI 看不见） |
| 起步框架 | Arduino (STM32duino) | 三行点灯，专注链路而非语法 | 直接上 HAL（第一天就被时钟配置劝退） |
| 平台 | Vite + React + TS，纯本地 | Node 已有，零后端，markdown 即数据库 | Next.js / 数据库（过度设计） |
| 内容格式 | Markdown + 极简 frontmatter | 人和 AI 都能读写，git 管版本 | CMS / Notion（锁死在平台里） |
| 路由 | hash 路由 | 不需要服务器配置，`file://` 都能开 | react-router |

## 6. AI 在这个平台里的角色
现在（v0.1）：**AI 在平台外面**。平台提供提示词模板，用户去 Claude / Cursor 里问。
下一步（v0.2）：**AI 进平台**。在任务页边上加一个对话框，自动带上：当前任务内容、`hardware/board.md`、最近 3 篇日志、`prompts/04-ai-lies.md`。这样 AI 一开口就知道你的板子是什么、你卡在哪、它以前在哪骗过你。
再下一步（v0.3）：**AI 帮你写日志**。做完任务，把终端输出和对话丢给它，它生成日志草稿，你改。

## 7. 判断做得对不对
- 每周至少 3 篇日志，说明真的在学
- 每个任务卡的"常见坑"表格至少有一行是自己踩出来的，不是抄的
- 三个月后：找一个真门外汉，让 TA 只看平台不问我，能不能走完模块 0 和 1

## 9. v0.2 追加：Canvas（实验台）框架 · 2026-09-28 下午

### 为什么
任务卡是文字，门外汉需要**能动手的东西**。而且板子没到之前也应该能练。所以平台内置"canvas"：嵌在任务卡里的交互实验。

### 借鉴
用户自己在 companydata 项目里做过一套"技能实验室"（职业实操模拟）。最值得搬过来的四个模式：
1. **Canvas = 数据定义的规格 + 确定性引擎 + 事件流。** 规格写在 markdown 里，引擎是纯函数，跑出来的是事件流而不是一个分数。
2. **采过程不采结论。** 引脚翻转序列、串口输出、警告，都进事件流；AI 评审看的是代码 + 事件流。
3. **目标（goals）和规则（rules）分开。** goals 是"做到了什么"，rules 是"不该做什么"（比如没 pinMode 就 digitalWrite）。
4. **专家轨迹做标尺**（下一步）：同一个任务留一份参考实现的事件流，和学员的对照。

### 现在有的 canvas
| type | 干什么 | 用在 |
|---|---|---|
| `board` | 虚拟蓝药丸：CodeMirror 编辑器 + Arduino 子集转译成 JS 在 Web Worker 里跑 + SVG 板子（LED、按键、引脚灯）+ 串口监视器（双向）+ 目标检查 + AI 评审 | 0-3、1-1、1-2、1-3、2-1、2-2 |
| `pinout` | 交互引脚图，按功能过滤，悬停看说明，标注"是否亲测" | 0-2 |
| `pullup` | 上拉电阻：有/无上拉、按/不按、悬空干扰 | 1-2 |
| `led-circuit` | 拖电阻看电流，理解限流 | 1-1 |
| `resistor-color` | 拨色环读阻值 | 1-1 |

### 怎么嵌
markdown 里一个 ` ```canvas ` 代码块，`key: value` 写属性，`---` 之后是初始代码。平台的 `Markdown.tsx` 把正文切成 [markdown | canvas] 段，canvas 交给 `canvases/index.tsx` 的注册表渲染。**加一种新 canvas = 写一个 React 组件 + 注册一行。**

### 模拟器的边界（诚实说明）
- 不是编译器。是对"初学者会写的 Arduino 子集"做源码变换：去类型、函数变 async、`delay` 前加 `await`。
- 支持：`pinMode / digitalWrite / digitalRead / analogWrite / analogRead / delay / millis / Serial.*`、if/for/while、用户自定义函数、`#define`。
- 不支持：指针、struct、char 数组、switch、中断。碰到会明确报"模拟器暂不支持，真板子可以"。
- 时序是浏览器的 setTimeout，不是硬件精度。用来理解逻辑够了，不能用来调时序。

### AI 评审
`platform/server/index.mjs` 本地小服务，用 Anthropic SDK 调 `claude-opus-5`，system prompt 是"有耐心的嵌入式导师"，输入是任务 + 验收标准 + 代码 + 事件流摘要。没配密钥时退化为"复制提示词，自己去问 AI"，功能不断。

### 状态条
平台顶部实时显示：板子插上没（扫 /dev/cu.* 和 USB 列表）、PlatformIO 装了没、AI 配了没。目的：把"环境"这层门槛变成一眼能看到的三盏灯。

### 下一步候选
- `wiring` canvas：ST-Link 四根线怎么接，点线高亮
- `board` 加 OLED（I2C 模拟）和电位器（ADC 输入滑块），覆盖模块 3
- 专家轨迹对照：每个 board 任务带一份参考实现，事件流做 diff
- AI 生成任务卡 → 在模拟器里验收 → 通过才入库（lab 里 designBench 那套闭环）

## 11. 北极星："要有光" · 2026-09-28 深夜

### 场景
> 我说：**要有光。**
> AI：拿出套件里的红色 LED 和一只红红棕金的电阻（图）。LED 长脚插面包板 j5，短脚插 j7；电阻一端插 i7，另一端插负极轨。杜邦线从板子 PA1 到 j5，从 GND 到负极轨。（接线图）做好了点"我接好了"。
> 我：我接好了。
> AI：编译……烧录……好了。灯亮了吗？
> 我：亮了。
> AI：记进日志了。要不要让它眨？

这就是平台的终点：**用纯自然语言完成嵌入式的所有操作**。授人以渔（课程）和授人以鱼（AI 直接把事办了）是同一个界面。

### 我的判断
这个设计是对的，而且它不是课程之外的另一个产品，是课程的**执行层**。理由：
1. 门槛地图里 ①环境 ②终端 ③git ④链路 ⑤报错 五层，全部是"人在给机器当翻译"。让 AI 直接操作机器，这五层就不存在了。
2. 剩下的门槛只有一种：**物理世界里 AI 够不着的动作**。插线、按 BOOT 键、换根数据线、看灯亮没亮。这些正好用"指令卡"解决，和你在 Supabase 里跑 SQL 的体验一样：AI 写好，人复制/照做，回来点"完成"。
3. 课程不会被替代，反而更值钱：AI 每做一步都能解释"我为什么这么做"，学习发生在旁观和追问里。想学的人看解释，只想要结果的人直接点确认。

### 架构：一个 agent，五类工具，一种暂停
```
浏览器（对话面板 + 指令卡）
   │ SSE
本地服务 server/index.mjs  ← Claude API 工具循环（tool runner）
   │
   ├─ 读写工具   read_file / write_file（限定在 firmware/ 和 content/）
   ├─ 构建工具   pio_build / pio_upload / pio_monitor（读一段）/ serial_send
   ├─ 知识工具   read_pinout / read_board / read_journal / search_curriculum
   ├─ 模拟工具   sim_run（把代码丢进浏览器里的虚拟板子跑，回事件流）
   └─ 人的工具   ask_human({ kind, title, why, steps[], paste?, expect })   ← 暂停循环，渲染指令卡
```
`ask_human` 是核心。它是 AI 的一只"手"，只不过这只手是你。四种 kind：
| kind | 例子 | 卡片长什么样 |
|---|---|---|
| `wire` | 把 LED 接到 PA1 | 元件贴图 + 接线图 + "我接好了" |
| `press` | 按住 BOOT0 再按 RESET | 板子贴图上高亮那个键 + "按了" |
| `paste` | 在终端跑这条命令 / 把这段贴进 .env | 可复制块 + "跑完了，输出是…" 输入框 |
| `observe` | 灯亮了吗？串口出字了吗？ | 选项按钮：亮了 / 没亮 / 闪一下就灭 |

人回答的每一句都进事件流，和模拟器的事件流一样，是**过程数据**。AI 根据回答决定下一步，日志自动生成。

### 上下文注入（AI 一开口就知道的事）
当前任务卡、`hardware/board.md`（板子是谁、引脚亲测表）、`prompts/04-ai-lies.md`（它以前在哪骗过你）、最近 3 篇日志、`check-env` 的结果。引脚号一律从 `pinout` 数据里取，不允许凭记忆。

### 安全边界
- 写文件只能写 `firmware/` 和 `content/`，不碰平台代码和系统
- `pio_upload` 直接执行（烧错了最多板子不亮，重烧就好）；安装类、删除类、改系统的动作**不给工具**，只能走 `ask_human(paste)`，由人来跑
- 每次工具调用在面板里可见：命令、输出、耗时。透明是信任的来源

## 12. 知识库与"部署后不更新" · 2026-09-28 深夜

### 目标
最终形态是一个**部署后可以很多年不更新**的平台：好奇"这个专业学什么"的中学生、想自己做点东西的年轻人，打开就能体验，能做出东西。做到这一点靠两条：
1. **AI 的本事攒在资料里，不攒在模型里。** 模型是租的、会换；资料是我们的，一次编好长期有效。嵌入式入门用的元件、项目、坑、术语二十年没大变。
2. **没有后端也能跑。** 课程、实验台、虚拟板子、知识库全部打包进静态前端；AI 对话可以用访客自己的密钥直接从浏览器调模型。真烧录需要本地服务，那是"进阶模式"。

### 五个知识库（content/knowledge/ + content/hardware/）
| 库 | 文件 | 规模 | AI 工具 | 编法 |
|---|---|---|---|---|
| 元件库 | hardware/parts-catalog.json | ~130 件：接口、电压、价格、搜索词、库、引脚、接法、最小代码、坑 | search_parts / part_detail | 一次性汇编，AI 可 add_part |
| 项目食谱 | knowledge/projects.json | 30 个：零件、接线、分步、代码骨架、坑、可否虚拟板子先做 | search_projects | 一次性汇编 |
| 排障库 | knowledge/troubleshooting.json | ~60 条：症状 → 原因(按概率) → 一分钟验证 → 解决 | search_troubleshooting | 一次性 + 日志里踩的坑回填 |
| 术语表 | knowledge/glossary.json | ~120 词：比喻、定义、误解、例子 | explain_concept | 一次性汇编 |
| 代码片段 | knowledge/snippets.json | ~35 段：可编译最小程序 + 逐段解释 | get_snippet | 一次性汇编 |
| 板子档案 | hardware/boards/*.json | 蓝药丸、Nucleo F103/F411、ESP32、UNO | list_boards / read_board_profile | 一次性汇编 |

### 检索在浏览器里

### 知识库上线后的第一次实测（2026-09-28 深夜）
输入："我想做一个电子骰子，按一下随机亮一个数。我只有蓝药丸，先在虚拟板子上做。"

对比知识库上线前（自动浇花那次）：那次它从零设计、查了 5 次元件库；这次直接以食谱为底稿，步骤更少、结果更稳。这就是"本事攒在资料里"的意思。

## 13. 路线图 · 2026-09-29（用户在纽约提出）
1. **i18n。** 英文版以美国用户为主：元件库要有美元价格和海外购买渠道（Amazon / Adafruit / SparkFun / DigiKey），课程与术语表要有英文版，AI 的系统提示按语言切换。内容表加 `lang` 字段，前端按用户语言取。
2. **两种模式，两条故事线。** "开发模式"（vibe：直接做 + 项目管理 + 硬件管理 + 采购）和"学习模式"（学习路径 + 实验台 + 日志 + 知识库）。首页先选模式，导航按模式收敛，每条线的故事更简单。项目和库存是两条线共享的底座。
3. **字要大要粗。** 面向年轻人和老年人；深色底上小字尤其难看。基础字号上调，标题加粗，中文用更粗的字重。参考 Scrimba 的课程卡和 Replit 的对话面板：大标题、留白、卡片信息少而清楚。
4. **开发模式要有足够的预览空间。** 参考 Replit：左边对话、右边一大块预览（虚拟板子、接线图、串口、以后是原理图和 PCB）。当前右栏只有 340px，要改成可拖拽的分栏，预览至少占一半。

优先级建议：3（半天）→ 4（一天）→ 2（两天，主要是信息架构）→ 1（内容量最大，分批做）。

## 14. 网页版直接烧硬件（2026-09-29 提出，方案）
浏览器不是只能"看"。Chrome 系的 Web Serial / WebUSB 可以直接和板子说话，所以线上版也能烧真板子，分两段：
1. **云编译**：Vercel 函数跑不了 PlatformIO，需要一个小容器服务（Fly.io / Railway，一个装了 PlatformIO 的 Docker），接口 `POST /compile {files} → firmware.bin`。编译一次十几秒，缓存框架后几秒。
2. **浏览器烧录**：
   - ESP32：`esptool-js`（Espressif 官方 JS 库，Web Serial），成熟。
   - STM32 走串口引导程序：BOOT0 跳线拨到 1，用 CH340 接 PA9/PA10，实现 STM32 的 UART bootloader 协议（AN3155，~200 行 JS），Web Serial 直接烧。
   - STM32 走 ST-Link：WebUSB 版 st-link（开源项目 webstlink）可以做，但 ST-Link 克隆固件差异大，作备选。
指令卡多一种 `flash`：浏览器弹出串口选择框，用户选设备，进度条，烧完自动复位。工具 `web_flash` 在浏览器执行，替代本地模式的 `pio_upload`。

## 15. 元件实体库（2026-09-30 / 10-01）

### 为什么
门外汉最常卡的不是概念，是**对不上号**：AI 说"接 HC-SR04 的 Echo"，用户不知道桌上四十个东西里哪个是它。名字和实物之间没有桥。

### 做法
`Markdown.tsx` 是全平台正文的唯一渲染出口，所以在那里做实体识别，**一处改动，聊天和课程任务卡同时生效**。

- **识别**：从 `parts-catalog.json` 建别名索引，扫 DOM 文本节点。只认带数字且 ≥4 字符的型号串（HC-SR04、ULN2003），挡掉 I2C、5V 这类总线和单位；代码块、链接里不标；一条消息里同一个元件只标第一次。
- **抽屉**：图、分类、接口/电压/引脚/接线/库、常见坑、最小代码、用在哪些项目、一起用的零件、购买链接（英文去 Amazon，中文去淘宝）。
- **相关配件白捡**：不另建关系表，从 30 个项目食谱里"一起出现过"推出来。
- **管理员**：`/admin` 多一个元件库 tab，全库可搜可点。

### 两层配图：PGC + UGC
示意图（通义万相生成）告诉你"这类东西长什么样"，**用户自己拍的实物照**告诉你"你手里这个是哪个版本"——正是 LCD1602 那条坑（I2C 版还是并口版）需要的。

传照片时先让模型核对"这真的是它吗"。**故意不做硬拦截**：模型看走眼是常事（见 `prompts/04-ai-lies.md`），说不是时给理由和"它更像什么"，由用户拍板；用户坚持保存的，把当时的异议一并记下。照片存 `storage.ts`（登录走 Supabase visitor_kv，否则 localStorage），压到 640px jpeg。

### 贴图质检：一个诚实的结论
用同一个核验接口给生成的贴图做质检（`npm run art:qa`），42 张里只有 16 张能被认出来。重写提示词再生成一轮，通过数几乎没变，有些反而更糟（薄膜键盘画成带市电插头的墙壁开关、SG90 舵机画成扳把开关盒）。

**结论：这个文生图模型画不准具体电子元件。** 认不出的 10 张直接删掉，回落到分类占位图标——新手拿一张错图去认零件，比没有图更糟。这不是功能缺失，是和"只记亲测"同一条原则。

### 经验
- flex/grid 项目的 `min-width: auto` 不小于内容固有宽度，所以给图写 `width/height: 100%` 会被顶成正方形、上下被裁掉。要用 `auto` + `max-*: 100%`。
- 负面提示词里禁"文字/数字"会把形状一起扭曲（键盘连键位标注都没了）。真实元件本来就有丝印，不该硬禁。

## 16. 接入 Nebius Token Factory + NVIDIA Nemotron（2026-10-06）

### 为什么
参加 Nebius × NVIDIA Global AI Hackathon（Physical AI 赛道，截止 10-30）。硬性要求：跑在 Nebius 上，且至少用一个 NVIDIA 开源模型。

### 改了什么
规格集中在 `shared/spec.mjs` 一处，这次的收益兑现了：接入只是**加一个适配器**，不是重写。

Nebius 兼容的是经典的 `/chat/completions`，不是 OpenAI 新的 `/responses`，两者结构不同：
- `tool_result` 要拆成独立的 `role:'tool'` 消息，不能塞进 user 消息
- assistant 的文字和这一轮所有 `tool_use` 要合成一条带 `tool_calls`
- 用量字段 `prompt_tokens/completion_tokens` 要归一成 Anthropic 口径，`usageRecord` 才算得对

`provider()` 认 `nebius`；本地服务和 Vercel 函数共用同一个适配器。

### 实测（真实密钥，不是推测）
- **30 个工具定义下首次命中**，Super 和 Nano 都准确选对工具
- **每步约 1 秒**，比原来用的模型还快
- **多轮循环稳定**：工具结果回灌后继续推进；某个工具报错会换一个，不死循环
- 静态模式（25 个工具）同样通过

原本最担心"换模型后工具调用会崩"，没有发生。

### 可用模型（从 `/models` 实际拉取）
`nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`、`nvidia/nemotron-3-super-120b-a12b`（默认）、`nvidia/Nemotron-3-Ultra-550b-a55b`、`nvidia/Nemotron-3_5-Lightning`。
Base URL：`https://api.studio.nebius.com/v1`（实测可用）。

### 部署隔离
`main` 继续用 OpenAI 跑正式站点，`nebius` 分支用 Nemotron 跑预览地址，环境变量在 Vercel 里按 Preview 作用域分开。**改造前的状态打了标签 `v1.0-openai`，随时能回去。**

### 踩的坑
从网页表格复制环境变量的值，**把制表符一起带进去了**，报 "The model `\tnvidia/...` does not exist"——名字肉眼看是对的，极难查。现在所有环境变量读取时一律 `trim()`。

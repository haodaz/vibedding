# 平台框架设计 v0.1

日期：2026-09-28 · 状态：第一版，板子还没到

## 0. 使命
把门槛拆掉，让人专注宝贵的部分：**实现自己的一个思路，对一件事大胆尝试，在一个原本无法掌握的领域做出点价值。**

门槛（环境、终端、git、报错、链路）是内行的日常、门外汉的高墙。它们不产生价值，只是挡在价值前面。平台的工作就是把这些墙一块块拆成台阶。见 [02-barrier-map.md](02-barrier-map.md)。

## 1. 我们在做什么
一个**边学边长**的平台。它有两个用户：
- **现在的我**：需要一条清晰的路、一个记录的地方、一套问 AI 的方法
- **以后的门外汉**：拿到一块板子和一个 AI，想知道从哪开始、下一步做什么、AI 说的能不能信

这两个用户的需求高度重合，所以"我学习时产生的东西"经过很少的整理就是"给别人的课程"。这是整个设计的核心押注。

## 2. 三层内容模型
```
日志 (journal)        原始、按天、有情绪、有弯路        →  真实
   ↓ 提炼
任务 (curriculum)     结构化、有验收、有常见坑          →  可复用
   ↓ 沉淀
提示词 & 硬件笔记      跨任务的方法论和事实             →  可信
```
- 日志是**源头**，写得越真实越好，包括 AI 说错的地方
- 任务是**产品**，每张卡都要能让一个陌生人独立完成
- 提示词库和硬件笔记是**基础设施**，每个任务都会引用它们

## 3. 一张任务卡的结构
```
frontmatter: title / goal / hardware / time / status
要做什么      一段话，说清楚为什么做这个
步骤          命令能直接复制
验收          checkbox，可观察的现象，不是"理解了 X"
问 AI 的时候  这个任务特有的提问建议
常见坑        表格：现象 → 原因
```
`goal` 必须是一个**看得见的结果**。"LED 眨眼"可以，"理解 GPIO"不行。

## 4. 课程路线（v0.1）
| 模块 | 主题 | 核心概念 | 为什么在这个位置 |
|---|---|---|---|
| 0 起飞前 | 工具链、认板子、第一次烧录 | 编译 → 烧录链路 | 消除硬件恐惧，先看到灯亮 |
| 1 点灯 | GPIO 输出/输入、PWM | 电平、上拉、占空比 | 最便宜的教具，建立肌肉记忆 |
| 2 会说话 | 串口收发 | UART、波特率 | 解锁 printf 调试，效率翻倍 |
| 3 感知世界 | ADC、传感器库、I2C 屏 | 模拟量、总线、第三方库 | 套件里的模块开始有用 |
| 4 时间的艺术 | millis、中断、状态机 | 非阻塞、volatile | 从"玩"到"能做东西"的分水岭 |
| 5 剥洋葱 | HAL、寄存器、读手册 | 时钟树、寄存器映射 | 有了直觉再看底层，不会被吓跑 |
| 6 综合项目 | 自选题目 | 需求拆解 | 把碎片拼成作品 |
| 7+（远期） | RTOS、低功耗、SPI/CAN、PCB | | 视兴趣 |

技术路线：**Arduino 框架起步 → HAL → 寄存器**。同一个 blink 写三遍，每一遍都比上一遍更接近硅片。

## 5. 技术选型
| 选择 | 方案 | 理由 | 放弃了什么 |
|---|---|---|---|
| 固件构建 | PlatformIO CLI | 命令行，AI 能直接跑；自动装编译器；跨板子 | STM32CubeIDE（图形界面，AI 看不见） |
| 起步框架 | Arduino (STM32duino) | 三行点灯，专注链路而非语法 | 直接上 HAL（第一天就被时钟配置劝退） |
| 平台 | Vite + React + TS，纯本地 | Node 已有，零后端，markdown 即数据库 | Next.js / 数据库（过度设计） |
| 内容格式 | Markdown + 极简 frontmatter | 人和 AI 都能读写，git 管版本 | CMS / Notion（锁死在平台里） |
| 路由 | hash 路由 | 不需要服务器配置，`file://` 都能开 | react-router |

## 6. AI 在这个平台里的角色
现在（v0.1）：**AI 在平台外面**。平台提供提示词模板，用户去 Claude / Cursor 里问。
下一步（v0.2）：**AI 进平台**。在任务页边上加一个对话框，自动带上：当前任务内容、`hardware/board.md`、最近 3 篇日志、`prompts/04-ai-lies.md`。这样 AI 一开口就知道你的板子是什么、你卡在哪、它以前在哪骗过你。
再下一步（v0.3）：**AI 帮你写日志**。做完任务，把终端输出和对话丢给它，它生成日志草稿，你改。

## 7. 判断做得对不对
- 每周至少 3 篇日志，说明真的在学
- 每个任务卡的"常见坑"表格至少有一行是自己踩出来的，不是抄的
- 三个月后：找一个真门外汉，让 TA 只看平台不问我，能不能走完模块 0 和 1

## 9. v0.2 追加：Canvas（实验台）框架 · 2026-09-28 下午

### 为什么
任务卡是文字，门外汉需要**能动手的东西**。而且板子没到之前也应该能练。所以平台内置"canvas"：嵌在任务卡里的交互实验。

### 借鉴
用户自己在 companydata 项目里做过一套"技能实验室"（职业实操模拟）。最值得搬过来的四个模式：
1. **Canvas = 数据定义的规格 + 确定性引擎 + 事件流。** 规格写在 markdown 里，引擎是纯函数，跑出来的是事件流而不是一个分数。
2. **采过程不采结论。** 引脚翻转序列、串口输出、警告，都进事件流；AI 评审看的是代码 + 事件流。
3. **目标（goals）和规则（rules）分开。** goals 是"做到了什么"，rules 是"不该做什么"（比如没 pinMode 就 digitalWrite）。
4. **专家轨迹做标尺**（下一步）：同一个任务留一份参考实现的事件流，和学员的对照。

### 现在有的 canvas
| type | 干什么 | 用在 |
|---|---|---|
| `board` | 虚拟蓝药丸：CodeMirror 编辑器 + Arduino 子集转译成 JS 在 Web Worker 里跑 + SVG 板子（LED、按键、引脚灯）+ 串口监视器（双向）+ 目标检查 + AI 评审 | 0-3、1-1、1-2、1-3、2-1、2-2 |
| `pinout` | 交互引脚图，按功能过滤，悬停看说明，标注"是否亲测" | 0-2 |
| `pullup` | 上拉电阻：有/无上拉、按/不按、悬空干扰 | 1-2 |
| `led-circuit` | 拖电阻看电流，理解限流 | 1-1 |
| `resistor-color` | 拨色环读阻值 | 1-1 |

### 怎么嵌
markdown 里一个 ` ```canvas ` 代码块，`key: value` 写属性，`---` 之后是初始代码。平台的 `Markdown.tsx` 把正文切成 [markdown | canvas] 段，canvas 交给 `canvases/index.tsx` 的注册表渲染。**加一种新 canvas = 写一个 React 组件 + 注册一行。**

### 模拟器的边界（诚实说明）
- 不是编译器。是对"初学者会写的 Arduino 子集"做源码变换：去类型、函数变 async、`delay` 前加 `await`。
- 支持：`pinMode / digitalWrite / digitalRead / analogWrite / analogRead / delay / millis / Serial.*`、if/for/while、用户自定义函数、`#define`。
- 不支持：指针、struct、char 数组、switch、中断。碰到会明确报"模拟器暂不支持，真板子可以"。
- 时序是浏览器的 setTimeout，不是硬件精度。用来理解逻辑够了，不能用来调时序。

### AI 评审
`platform/server/index.mjs` 本地小服务，用 Anthropic SDK 调 `claude-opus-5`，system prompt 是"有耐心的嵌入式导师"，输入是任务 + 验收标准 + 代码 + 事件流摘要。没配密钥时退化为"复制提示词，自己去问 AI"，功能不断。

### 状态条
平台顶部实时显示：板子插上没（扫 /dev/cu.* 和 USB 列表）、PlatformIO 装了没、AI 配了没。目的：把"环境"这层门槛变成一眼能看到的三盏灯。

### 下一步候选
- `wiring` canvas：ST-Link 四根线怎么接，点线高亮
- `board` 加 OLED（I2C 模拟）和电位器（ADC 输入滑块），覆盖模块 3
- 专家轨迹对照：每个 board 任务带一份参考实现，事件流做 diff
- AI 生成任务卡 → 在模拟器里验收 → 通过才入库（lab 里 designBench 那套闭环）

## 11. 北极星："要有光" · 2026-09-28 深夜

### 场景
> 我说：**要有光。**
> AI：拿出套件里的红色 LED 和一只红红棕金的电阻（图）。LED 长脚插面包板 j5，短脚插 j7；电阻一端插 i7，另一端插负极轨。杜邦线从板子 PA1 到 j5，从 GND 到负极轨。（接线图）做好了点"我接好了"。
> 我：我接好了。
> AI：编译……烧录……好了。灯亮了吗？
> 我：亮了。
> AI：记进日志了。要不要让它眨？

这就是平台的终点：**用纯自然语言完成嵌入式的所有操作**。授人以渔（课程）和授人以鱼（AI 直接把事办了）是同一个界面。

### 我的判断
这个设计是对的，而且它不是课程之外的另一个产品，是课程的**执行层**。理由：
1. 门槛地图里 ①环境 ②终端 ③git ④链路 ⑤报错 五层，全部是"人在给机器当翻译"。让 AI 直接操作机器，这五层就不存在了。
2. 剩下的门槛只有一种：**物理世界里 AI 够不着的动作**。插线、按 BOOT 键、换根数据线、看灯亮没亮。这些正好用"指令卡"解决，和你在 Supabase 里跑 SQL 的体验一样：AI 写好，人复制/照做，回来点"完成"。
3. 课程不会被替代，反而更值钱：AI 每做一步都能解释"我为什么这么做"，学习发生在旁观和追问里。想学的人看解释，只想要结果的人直接点确认。

### 架构：一个 agent，五类工具，一种暂停
```
浏览器（对话面板 + 指令卡）
   │ SSE
本地服务 server/index.mjs  ← Claude API 工具循环（tool runner）
   │
   ├─ 读写工具   read_file / write_file（限定在 firmware/ 和 content/）
   ├─ 构建工具   pio_build / pio_upload / pio_monitor（读一段）/ serial_send
   ├─ 知识工具   read_pinout / read_board / read_journal / search_curriculum
   ├─ 模拟工具   sim_run（把代码丢进浏览器里的虚拟板子跑，回事件流）
   └─ 人的工具   ask_human({ kind, title, why, steps[], paste?, expect })   ← 暂停循环，渲染指令卡
```
`ask_human` 是核心。它是 AI 的一只"手"，只不过这只手是你。四种 kind：
| kind | 例子 | 卡片长什么样 |
|---|---|---|
| `wire` | 把 LED 接到 PA1 | 元件贴图 + 接线图 + "我接好了" |
| `press` | 按住 BOOT0 再按 RESET | 板子贴图上高亮那个键 + "按了" |
| `paste` | 在终端跑这条命令 / 把这段贴进 .env | 可复制块 + "跑完了，输出是…" 输入框 |
| `observe` | 灯亮了吗？串口出字了吗？ | 选项按钮：亮了 / 没亮 / 闪一下就灭 |

人回答的每一句都进事件流，和模拟器的事件流一样，是**过程数据**。AI 根据回答决定下一步，日志自动生成。

### 上下文注入（AI 一开口就知道的事）
当前任务卡、`hardware/board.md`（板子是谁、引脚亲测表）、`prompts/04-ai-lies.md`（它以前在哪骗过你）、最近 3 篇日志、`check-env` 的结果。引脚号一律从 `pinout` 数据里取，不允许凭记忆。

### 安全边界
- 写文件只能写 `firmware/` 和 `content/`，不碰平台代码和系统
- `pio_upload` 直接执行（烧错了最多板子不亮，重烧就好）；安装类、删除类、改系统的动作**不给工具**，只能走 `ask_human(paste)`，由人来跑
- 每次工具调用在面板里可见：命令、输出、耗时。透明是信任的来源
